# 核心体验重制计划

状态：2026-09-06。本文件保留视觉链路的细化验收；砍项、广告位、APK 证据分层、真人联机门槛和完整阶段计划统一见 [LAUNCH_REDESIGN_SPEC.md](LAUNCH_REDESIGN_SPEC.md)。当前首页与五 Tab 的 v2 整理只作为可测基线，不能当作视觉重制完成报告。

## 第一条交付链路

先完成「首页 → 地下城探索 → 结算 → 返回继续冒险」，用一条完整可玩的链路确定最终视觉水平。暂定沿用自有猿岛品牌和像素冒险方向，禁止用未经核验的原产品素材填补美术质量。

| 页面/状态 | 要解决的问题 | 具体交付 |
|---|---|---|
| 首页 | 玩家进入后首先看到功能列表，缺少地点与角色关系 | 正式岛屿场景、清晰角色主体、进度提示、单一主行动和少量日常入口 |
| 地下城进入 | 数字按钮缺少探索语义，消耗说明过小 | 砖块材质、层数与探索进度、金币/门票消耗、明确可交互区域 |
| 地下城操作 | 揭开与奖励主要靠文字反馈 | 未探索/处理中/已揭开/不可用四种可辨状态；揭开动画、命中反馈和当前收获 |
| 结算 | 收获分散，缺少结束感及下一步 | 奖励构图、资产变化、继续探索/返回主城、失败和不足时的可恢复状态 |

奖励数值仍以权威服务端响应为准；断网或提交未确认时不能提前展示确定到账。视觉动画不能重新触发经济请求，也不能因自动重试重复播放成功发奖。

## 同步建立的规范

- 角色比例、像素网格、场景视角和光源统一；图集与游戏画面一起审查。
- 字体明确区分标题、正文、辅助信息和数值；核心消耗、奖励及错误文案在常用手机尺寸上可读。
- 主按钮、次按钮、选中、禁用、处理中和错误状态共用组件；主操作命中区域至少 44 × 44 CSS px。
- 图标使用统一素材与语义；菜单不再靠大段小字说明功能。
- 每个动作有及时反馈，处理中状态阻止重复操作；弹窗和动效不覆盖仍需点击的区域。

正式素材替换占位资源时重新检查 4 MiB 主包门禁、CDN 引用、加载/缺图表现和权利链。资源数量或图集调用次数不作为美术完成指标。

## 扩展顺序

1. 大逃杀：房间、门、敌我状态、回合行动和胜负结算。
2. 卡牌：完整卡面、稀有度、获得反馈、收集与合成进度。
3. 养成与我的：角色成长、资产与任务进度、账户服务。
4. 其余玩法：按复用场景和交互组件扩展，逐屏记录差异。

## 验收方式

每条链路交付进入、操作、奖励和失败四种真实运行截图，配合实际点击和返回验证。覆盖短屏、长文案、弱网、重复操作、缺图和安全区域；真机点击与观感单独记录，模拟器和几何断言不能替代。

原型占位稿、设计稿、已接入代码、模拟器通过和真机通过分别标识。全链路视觉未通过前，不把某一张首页截图扩大为全游戏完成。
